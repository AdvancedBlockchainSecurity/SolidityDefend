## What changed since v2.0.14 (ADV-231)

Three detectors were corrected. Every fix was grounded in source inspection —
no finding was suppressed to move the metric, and **no `known_false_positives`
entries were used**.

- **centralization-risk 72 → 20.** `check_contract_centralization` read the
  whole file rather than the contract under analysis. Since the registry runs
  once per contract, one `selfdestruct` anywhere in a file invented a finding
  for every contract in it — 46 of the 72 were flagged on contracts containing
  no `selfdestruct` at all. Also required an owner gate before claiming
  "controllable by single address", and made the timelock heuristic
  case-insensitive.
- **block-dependency 21 → 5.** `is_deadline_comparison` only ever saw `if`
  conditions, so it was dead code for `require(block.timestamp <= deadline)`.
  Added `timestamp_used_dangerously`: a block value merely stored or passed as a
  deadline argument is bookkeeping; it only matters when it feeds a hash
  (randomness) or a modulo (selection).
- **gas-griefing 13 → 4.** The detector never asked who controls the batch. In
  the Multicall/ERC-7821 pattern the caller supplies the targets and pays the
  gas, so a callee burning gas only fails the submitter's own transaction.

Also fixed (ADV-230): contract-level findings hardcoded line 1, so the CLI's
`(detector, file, line)` dedup collapsed distinct contracts. Shipped together
with the tuning, so net output fell (144 → 132) rather than rose.

Triage established that a large share of the remainder is **stale ground truth**
rather than detector error: 18 of the 20 centralization-risk and 4 of the 5
block-dependency findings are genuinely real and simply were never annotated.
Annotating them converts FP → TP and raises precision further without touching a
detector.

precision is a tracked reference, not yet a target.
